<!-- sdlc:auto:start overview -->
sonartest is a small time-scheduler app for cross-timezone team collaboration, generated by the Quorq AI SDLC platform as two separate applications in one repo. The `frontend/` is an approved Vite + React 19 SPA whose screens currently render seeded sample data rather than live API calls. The `backend/` is a FastAPI 0.115 service that was generated before any backend architecture was approved, so it currently only exposes a `/health` endpoint, backed by SQLAlchemy models/tables that don't exist yet and a SQLite database by default (swappable to Postgres via `DATABASE_URL`).
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm/Vite/React 19 tooling)
- Python 3.12 (matches backend/Dockerfile base image)
- pip
- Docker and Docker Compose (optional, for the Postgres service in docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. cd frontend && npm install
3. cd backend && pip install -r requirements.txt
4. (optional) copy .env.example to .env and set values such as DATABASE_URL / ALLOWED_ORIGINS / VITE_API_BASE_URL for your environment
5. (optional) docker-compose up db -d to run a local Postgres 16 instance if you don't want the default SQLite file
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one router per architecture component that owns endpoints, one route per spec'd endpoint (backend/app/routers/)
- Every unimplemented backend route returns a typed StubResponse (status: not_implemented) rather than raising, so OpenAPI stays complete
- SQLAlchemy models all inherit from the shared Base in app/database.py; models.py is imported in main.py before create_all so tables register
- Backend session handling is request-scoped via the get_db dependency generator
- SQLite is the default DATABASE_URL for zero-setup local runs; swap via env var for Postgres/MySQL without code changes
- Frontend screens are generated from approved designs and intentionally still use seeded sample data, not live API calls, until wired up
- Frontend API access is centralized in src/lib/api.ts (apiFetch) with bearer auth via a shared secret or session token in localStorage
- Frontend component tests live beside the components they cover and are scoped to src/**/*.{test,spec}.{ts,tsx}; Playwright specs live separately in e2e/
- Linting/formatting enforced via ESLint + Prettier (frontend) and Ruff (backend)
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend calls to the backend are blocked by the browser (CORS) | Set ALLOWED_ORIGINS (comma-separated) in the backend environment to match the frontend's origin; defaults only allow http://localhost:5173 and http://127.0.0.1:5173 |
| `pytest` fails with ImportError for `app` | Run pytest from the backend/ directory so pytest.ini's pythonpath = . is in effect |
| `npm run build` succeeds but deployment/type errors appear later | Run `npm run typecheck` (tsc --noEmit) since build does not typecheck and generated screens can have untyped state bugs |
| Playwright e2e tests fail to start the backend | Ensure backend dependencies are installed into backend/.venv (the webServer command in playwright.config.ts invokes .venv/bin/python directly) |
| Backend has no persisted data between runs | Default DATABASE_URL is sqlite:///./app.db with no migrations; point DATABASE_URL at the docker-compose Postgres service or another real database when data needs to persist |
<!-- sdlc:auto:end troubleshooting -->
